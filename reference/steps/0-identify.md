# 0. Classify the documents and settle their identity

Classify each file: target / reference / review. If unsure, ask the user; if the user is unavailable, write your guess at the top of the report. Identify which documents are IMMUTABLE (e.g. a Project Report) and use them as reference only. Create a working folder `work/`; intermediate files live there.

**Document identity.** Run `section_inventory.py identity` with EVERY document name the user used ("Ek B", "PAR", "charter"), after `extract.py` has produced the target text. Possible outcomes:
- `file`: matched to an uploaded file (correct a wrong or ambiguous match with `--map "name=file"`). If it is the target itself, that is a circular check.
- `internal-section`: no such file, but the target has a section of that name. Never treat this as the same thing silently. ASK the user whether a separate document exists. If the user is unavailable, the note ("«Ek B» was not provided as a separate file; the section «Appendix B» of the target was used") stays at the top of the report; use `--lang tr` for a Turkish report; record an answer with `--confirmed "name=answer"`. Add the section to the section inventory (`scan … "work/ex/target.txt@Appendix B"`). Rules taken from it keep their normal result (do not turn them into ❓): the report marks them `⚑ source assumption` and lists them as a circular check (the target verifies itself).
- `missing`: neither. Ask; otherwise it is counted as a skipped check.

**Tracked changes in a PDF.** `extract.py` (needs pdfplumber) detects text under a strikeout annotation or crossed by a drawn line. It then writes `<stem>.current.txt` (deleted text removed, same `p:L` locations) and `<stem>.changes.json` (page, deleted/added text). Read and quote `current.txt`; the scripts use it automatically when given `<stem>.txt`, and `verify` rejects a rule quoting deleted text. Check the rest in `changes.json`: `suspected` runs (red/grey without a line) are NOT removed, and `unremoved` deletions are still in the text: open those pages. Page images still show deleted text. If detection did not run, the report counts it as skipped; for `doc_diff.py` pass the `.txt` files, not the PDFs.

**Own ID prefixes.** Right after `extract.py`, run `prefixes.py work/ex/*.txt` on the target AND every reference. If a document already uses `R`, `F`, `TBD` or `IF` as an ID prefix (hyphenated or not, e.g. risk rows "R7"), that kind switches to `RC-R-`, `RC-F-`, `RC-TBD-` or `RC-IF-`. Use the chosen prefixes in EVERY work file (register, results, `tbd.json`, `internal.json`); wherever these instructions write `R-`, `F-`, `TBD-`, `IF-`, they mean the chosen ones. The choice is stated at the top of the report and `verify` enforces it. IDs that appear only inside images are not detected: if you see one that collides, tell the user.

The identity step is mandatory. If the user named no document at all, record it: `progress.py step work/progress.json identity skipped --reason "the user named no document"`.
